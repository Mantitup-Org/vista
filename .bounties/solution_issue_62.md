## Root Cause Analysis and Solution Strategy

The core issue is that `vista deploy` is not correctly generating platform-specific deployment artifacts, leading to various failures across different hosting environments. The `create-vista-app` now intentionally omits these files, placing the full responsibility on `vista deploy` to produce correct, runnable configurations.

I'll address each known failure mode systematically:

1.  **Cloudflare Pages (static) — `/rsc/*` Flight fetches get rewritten to HTML:**
    *   **Root Cause:** Cloudflare Pages' default `_redirects` behavior, combined with potentially incorrect or missing `_redirects` rules generated by Vista, causes `/rsc/*` requests to be treated as HTML navigation instead of RSC payloads. The issue description mentions "double `_redirects` / identity `.rsc` rule," suggesting a conflict or misconfiguration in how Vista instructs Cloudflare to handle these paths. Cloudflare Pages often requires explicit `_redirects` rules to prevent this.
    *   **Solution:** Ensure `vista deploy` for Cloudflare Pages generates a `_redirects` file that explicitly handles `/rsc/*` paths, ensuring they are served directly without rewriting or content-type changes. The key is to prevent Cloudflare from applying its default HTML rewrite logic to these specific API endpoints. An identity rewrite or a specific content-type header might be needed.

2.  **PPR shells — loading HTML must not inline the finished page Flight (`ppr-page-content` leak):**
    *   **Root Cause:** This indicates that the initial HTML shell for Partial Prerendering (PPR) is inadvertently including the full RSC payload, which defeats the purpose of PPR and can lead to larger initial payloads and hydration issues. The `ppr-page-content` is likely being rendered directly into the HTML instead of being fetched separately. This usually happens if the server-side rendering logic for PPR isn't correctly separating the shell from the dynamic content.
    *   **Solution:** Review the PPR rendering logic within Vista's core. The HTML shell should only contain the necessary static markup and client-side hydration markers, *not* the actual RSC data for the current page. The RSC data should be fetched by the client after the shell loads. This might involve adjusting how `renderToPipeableStream` or similar React APIs are used to ensure the `bootstrapModules` and `bootstrapScriptContent` are correctly configured without leaking the full page content.

3.  **Vercel / Netlify full SSR — standalone `.vista/standalone/server.js` missing:**
    *   **Root Cause:** For standalone SSR targets, `vista deploy` needs to bundle the entire server-side application, including `server.js` and its `node_modules`, into a deployable function/container. If `server.js` is missing, the deployment is incomplete. `--dry-run` should reflect this.
    *   **Solution:** Modify `vista deploy` to ensure that for Vercel, Netlify, and other standalone targets, the `.vista/standalone/server.js` file, along with its necessary `node_modules` dependencies, is correctly packaged into the output directory (e.g., `.vercel/output/functions`, `netlify/functions`). This likely involves a more robust bundling step for the server entry point.

4.  **Cloudflare Containers vs Pages — `wrangler.toml` / Dockerfile emitted when the user wanted static Pages (or the reverse):**
    *   **Root Cause:** `vista deploy` is likely making an incorrect assumption about the target Cloudflare environment or not providing a clear way for the user to specify their intent (Pages vs. Workers/Containers).
    *   **Solution:** Introduce or clarify a `--target` sub-option or a more explicit detection mechanism within `vista deploy` for Cloudflare. For example, `vista deploy --target cloudflare-pages` vs. `vista deploy --target cloudflare-workers` (or `cloudflare-container`). The current `--target cloudflare` should default to Pages if not specified, and `wrangler.toml` should only be generated for Workers/Containers.

5.  **Render / Docker — generated `startCommand` / `CMD` does not match `node .vista/standalone/server.js`:**
    *   **Root Cause:** The generated `render.yaml` or `Dockerfile` for Render/Docker deployments has an incorrect `startCommand` or `CMD` instruction, preventing the server from starting correctly.
    *   **Solution:** Ensure `vista deploy` generates `render.yaml` and `Dockerfile` with the correct `startCommand` (e.g., `node .vista/standalone/server.js`) for Render and `CMD ["node", ".vista/standalone/server.js"]` for Docker. This command must correctly point to the bundled server entry point.

6.  **Live regression — https://vistajs.pages.dev view-source dumps extra `clientN-*.js` tags, or docs links do a full document reload:**
    *   **Root Cause:**
        *   **Extra `clientN-*.js` tags:** This suggests that the client-side bundles are being incorrectly injected or duplicated, possibly due to a misconfiguration in the build process or the HTML templating.
        *   **Full document reload:** This is a classic sign that client-side routing is failing, and the browser is performing a full page navigation instead of an SPA-style client-side transition. This often happens if the client-side router isn't correctly initialized or if the server is returning HTML for RSC requests (related to point 1).
    *   **Solution:**
        *   **Extra tags:** Verify the HTML generation logic to ensure client scripts are injected only once and correctly. This might involve checking the `bootstrapModules` configuration in React's SSR.
        *   **Full reload:** This is likely a symptom of the Cloudflare Pages `_redirects` issue (point 1). If `/rsc/*` requests return HTML, the client-side router will fail to fetch the RSC payload and fall back to a full page reload. Fixing point 1 should resolve this. Also, ensure the client-side router is correctly initialized and configured to intercept link clicks.

```typescript
import { copyFile, mkdir, writeFile } from 'node:fs/promises';
import { join } from 'node:path';
import { fileURLToPath } from 'node:url';
import { existsSync } from 'node:fs';

import { getAppConfig } from '../config.js';
import { getBuildInfo } from '../build.js';
import { getLogger } from '../logger.js';
import { getProjectRoot } from '../utils.js';

const logger = getLogger('deploy:cloudflare');

export async function deployCloudflare(
  targetDir: string,
  options: { dryRun?: boolean; force?: boolean; type?: 'pages' | 'workers' },
) {
  const { dryRun, force } = options;
  const appConfig = await getAppConfig();
  const buildInfo = await getBuildInfo();
  const projectRoot = getProjectRoot();

  const outputDir = join(targetDir, '.vista', 'deploy', 'cloudflare');
  const staticDir = join(projectRoot, buildInfo.outputDir, 'static');
  const serverDir = join(projectRoot, buildInfo.outputDir, 'standalone');

  if (dryRun) {
    logger.info(`Dry run: Cloudflare deployment to ${outputDir}`);
  } else {
    await mkdir(outputDir, { recursive: true });
  }

  const deployType = options.type || 'pages'; // Default to 'pages'

  if (deployType === 'pages') {
    logger.info('Generating Cloudflare Pages deployment files...');

    // Copy static assets
    logger.info(`Copying static assets from ${staticDir} to ${outputDir}`);
    if (!dryRun) {
      await copyDir(staticDir, outputDir);
    }

    // Generate _redirects file for Cloudflare Pages
    // This is crucial for handling RSC requests correctly and preventing full reloads.
    // It ensures /rsc/* paths are not rewritten to HTML and are served directly.
    const redirectsContent = `
# Vista-specific redirects for Cloudflare Pages
# Ensure /rsc/* paths are served directly as Flight payloads
/rsc/* /rsc/:splat 200

# Fallback for client-side routing (if not handled by static assets)
# This ensures all non-static paths are routed to index.html for SPA behavior
# (Only if the path doesn't exist as a static file)
/* /index.html 200
`;
    const redirectsPath = join(outputDir, '_redirects');
    logger.info(`Generating _redirects file at ${redirectsPath}`);
    if (!dryRun) {
      await writeFile(redirectsPath, redirectsContent.trim());
    }

    // Cloudflare Pages typically serves `index.html` for all routes not found as static assets.
    // We need to ensure the root `index.html` is present.
    const indexHtmlPath = join(projectRoot, buildInfo.outputDir, 'index.html');
    if (existsSync(indexHtmlPath)) {
      logger.info(`Copying index.html to ${outputDir}`);
      if (!dryRun) {
        await copyFile(indexHtmlPath, join(outputDir, 'index.html'));
      }
    } else {
      logger.warn(`index.html not found at ${indexHtmlPath}. This might cause issues for Cloudflare Pages.`);
    }

    logger.info('Cloudflare Pages deployment files generated successfully.');
    logger.info('To deploy: `npx wrangler pages deploy <outputDir>`');
    logger.info(`Output directory: ${outputDir}`);
  } else if (deployType === 'workers') {
    logger.info('Generating Cloudflare Workers deployment files...');

    // Copy server bundle
    logger.info(`Copying server bundle from ${serverDir} to ${outputDir}`);
    if (!dryRun) {
      await copyDir(serverDir, outputDir);
    }

    // Generate wrangler.toml
    const wranglerTomlContent = `
name = "${appConfig.name || 'vista-app'}-worker"
main = "server.js"
compatibility_date = "2023-12-01" # Adjust as needed
`;
    const wranglerTomlPath = join(outputDir, 'wrangler.toml');
    logger.info(`Generating wrangler.toml at ${wranglerTomlPath}`);
    if (!dryRun) {
      await writeFile(wranglerTomlPath, wranglerTomlContent.trim());
    }

    // Copy static assets into a 'public' folder within the worker bundle if needed
    // For Workers, static assets are usually served by the worker itself or a separate R2 bucket.
    // For simplicity, we'll assume the worker serves them from its own bundle for now.
    const workerPublicDir = join(outputDir, 'public');
    logger.info(`Copying static assets from ${staticDir} to ${workerPublicDir}`);
    if (!dryRun) {
      await copyDir(staticDir, workerPublicDir);
    }

    logger.info('Cloudflare Workers deployment files generated successfully.');
    logger.info('To deploy: `npx wrangler deploy <outputDir>`');
    logger.info(`Output directory: ${outputDir}`);
  } else {
    logger.error(`Unknown Cloudflare deployment type: ${deployType}`);
  }
}

// Helper to copy directories recursively
async function copyDir(src: string, dest: string) {
  await mkdir(dest, { recursive: true });
  const entries = await readdir(src, { withFileTypes: true });

  for (const entry of entries) {
    const srcPath = join(src, entry.name);
    const destPath = join(dest, entry.name);

    if (entry.isDirectory()) {
      await copyDir(srcPath, destPath);
    } else {
      await copyFile(srcPath, destPath);
    }
  }
}

// Re-export for main deploy command
export { deployCloudflare as cloudflare };

// Add readdir for copyDir helper
import { readdir } from 'node:fs/promises';
```

**Explanation for `cloudflare.ts`:**
*   **Default to Pages:** `options.type || 'pages'` ensures Pages is the default.
*   **`_redirects` for Pages:** This is the critical fix for `/rsc/*` fetches. The rule `/rsc/* /rsc/:splat 200` tells Cloudflare Pages to serve these paths directly with a 200 status, preventing HTML rewriting. The `/* /index.html 200` is a standard SPA fallback.
*   **`index.html` copy:** Ensures the main entry point is available for Pages.
*   **Workers logic:** Separated for `wrangler.toml` and server bundle. Static assets are copied into a `public` folder within the worker bundle for self-serving.
*   **`copyDir` helper:** Added for recursive directory copying.

import { copyFile, mkdir, writeFile } from 'node:fs/promises';
import { join } from 'node:path';

import { getProjectRoot } from '../utils.js';

const logger = getLogger('deploy:vercel');

export async function deployVercel(
  targetDir: string,
  options: { dryRun?: boolean; force?: boolean },
) {
  const { dryRun } = options;
  const appConfig = await getAppConfig();
  const buildInfo = await getBuildInfo();
  const projectRoot = getProjectRoot();

  const outputDir = join(targetDir, '.vista', 'deploy', 'vercel');
  const staticDir = join(projectRoot, buildInfo.outputDir, 'static');
  const serverEntry = join(projectRoot, buildInfo.outputDir, 'standalone', 'server.js');

  if (dryRun) {
    logger.info(`Dry run: Vercel deployment to ${outputDir}`);
  } else {
    await mkdir(outputDir, { recursive: true });
  }

  logger.info('Generating Vercel deployment files...');

  // Vercel output structure:
  // .vercel/output/static/ -> static assets
  // .vercel/output/functions/index.func/ -> serverless function
  const vercelStaticDir = join(outputDir, 'static');
  const vercelFunctionsDir = join(outputDir, 'functions', 'index.func');

  // 1. Copy static assets
  logger.info(`Copying static assets from ${staticDir} to ${vercelStaticDir}`);
  if (!dryRun) {
    await mkdir(vercelStaticDir, { recursive: true });
    await copyDir(staticDir, vercelStaticDir);
  }

  // 2. Bundle serverless function
  logger.info(`Bundling serverless function from ${serverEntry} to ${vercelFunctionsDir}`);
  if (!existsSync(serverEntry)) {
    logger.error(`Server entry point not found: ${serverEntry}. Please ensure 'npm run build' was successful.`);
    throw new Error('Server entry point missing for Vercel deployment.');
  }

  if (!dryRun) {
    await mkdir(vercelFunctionsDir, { recursive: true });

    // Use ncc to bundle the server.js and its node_modules into a single file
    // This is crucial for Vercel's serverless function environment.
    logger.info('Using `ncc` to bundle server.js...');
    try {
      await execa('npx', ['ncc', 'build', serverEntry, '-o', vercelFunctionsDir, '-m', '--target', 'es2020', '--no-cache'], {
        cwd: projectRoot,
        stdio: 'inherit',
      });
      // ncc outputs index.js by default
      await copyFile(join(vercelFunctionsDir, 'index.js'), join(vercelFunctionsDir, 'server.js'));
      // Remove the ncc default index.js
      await rm(join(vercelFunctionsDir, 'index.js'));
    } catch (error) {
      logger.error(`Failed to bundle server.js with ncc: ${error}`);
      throw error;
    }

    // Create a config.json for the function
    const configJsonPath = join(vercelFunctionsDir, 'config.json');
    const configContent = {
      runtime: 'nodejs18.x', // Or nodejs20.x, depending on Vercel's latest support
      handler: 'server.js',
      maxDuration: 10, // Default max duration
      memory: 1024, // Default memory
    };
    logger.info(`Generating config.json for function at ${configJsonPath}`);
    await writeFile(configJsonPath, JSON.stringify(configContent, null, 2));
  }

  logger.info('Vercel deployment files generated successfully.');
  logger.info('To deploy: `npx vercel deploy <outputDir>`');
  logger.info(`Output directory: ${outputDir}`);
}

// Helper to copy directories recursively
async function copyDir(src: string, dest: string) {
  await mkdir(dest, { recursive: true });
  const entries = await readdir(src, { withFileTypes: true });

  for (const entry of entries) {
    const srcPath = join(src, entry.name);
    const destPath = join(dest, entry.name);

    if (entry.isDirectory()) {
      await copyDir(srcPath, destPath);
    } else {
      await copyFile(srcPath, destPath);
    }
  }
}

// Re-export for main deploy command
export { deployVercel as vercel };

// Add readdir and rm for copyDir helper and ncc cleanup
import { readdir, rm } from 'node:fs/promises';

**Explanation for `vercel.ts`:**
*   **Vercel Output Structure:** Adheres to Vercel's `.vercel/output` specification for static assets and serverless functions.
*   **`ncc` Bundling:** Uses `ncc` (a simple, fast bundler for Node.js) to package `server.js` and its `node_modules` into a single file. This is crucial for Vercel's serverless environment where `node_modules` are not automatically available.
*   **`config.json`:** Generates the necessary `config.json` for the serverless function, specifying runtime, handler, and other properties.
*   **Error Handling:** Checks for `server.js` existence.

      - key: NODE_ENV

// Helper to copy directories recursively
async function copyDir(src: string, dest: string) {
  await mkdir(dest, { recursive: true });
  const entries = await readdir(src, { withFileTypes: true });

  for (const entry of entries) {
    const srcPath = join(src, entry.name);
    const destPath = join(dest, entry.name);

    if (entry.isDirectory()) {
      await copyDir(srcPath, destPath);
    } else {
      await copyFile(srcPath, destPath);
    }
  }
}
